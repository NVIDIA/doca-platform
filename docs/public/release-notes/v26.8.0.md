---
title: "DOCA Platform Framework v26.8.0"
---

This is the GA release of the DOCA Platform Framework (DPF). It includes bug fixes
and improvements to enhance the provisioning and orchestration of NVIDIA BlueField
DPUs in Kubernetes environments.

### Revision History

| Date         | Description                                                           |
|--------------|-----------------------------------------------------------------------|
| August 2026  | General Availability (GA) release of DOCA Platform Framework v26.8.0  |

### Features

* **`NodeServiceInterfaces` API and default SFC path**
    * **Description:**
        This release introduces the `NodeServiceInterfaces` custom resource on the DPU cluster
        as a scaling improvement for SFC interfaces. Each object is a per-node shard that
        aggregates all interface entries for that node in the `dpf-operator-system` namespace,
        replacing the previous model of one legacy `ServiceInterface` object per interface per
        node. This reduces API object count from one CR per interface to one CR per node
        (for example, from tens of thousands of objects to one per DPU at large scale).
        Plain SFC interfaces (those without a `virtualNetwork`) use this path by default.
    * **Scope:**
        The default switch to `NodeServiceInterfaces` applies to SFC only. VPC interfaces
        (those with a `virtualNetwork`) continue to use the legacy `ServiceInterface` path in
        this release.
    * For details, see [NodeServiceInterfaces](../developer-guides/api/api.md#nodeserviceinterfaces).

### Installation & Upgrade Notes

#### Installation Notes

None.

#### Upgrade Notes

* **SFC interfaces auto-migrate to `NodeServiceInterfaces`**
    * **Description:**
        After upgrading to v26.8.0, SFC `ServiceInterfaceSet` resources (those without a
        `virtualNetwork`) are automatically moved onto the `NodeServiceInterfaces` path.
        On reconcile, the controller stamps `svc.dpu.nvidia.com/interface-mode: nsi`, creates
        the corresponding `NodeServiceInterfaces` entries, and deletes owned legacy per-node
        `ServiceInterface` children only after those NSI entries are Ready. No manual action
        is needed.
    * **Impact:**
        * Migration is make-before-break: NSI entries are created and must become Ready before
          legacy `ServiceInterface` objects are removed, so SFC traffic continuity is preserved
          during upgrade.
        * Operators and automation that inspect DPU-cluster interface objects should look for
          `NodeServiceInterfaces` in `dpf-operator-system` rather than per-node
          `ServiceInterface` objects for SFC.
        * VPC interfaces are not migrated in this release and continue to use
          `ServiceInterface` objects.
        * The legacy SFC `ServiceInterface` code path is planned for removal in a future
          release once migration has completed in the field.
    * **Verification:**
        ```bash
        # Interface mode on DPU-cluster ServiceInterfaceSets (SFC should report nsi)
        kubectl get serviceinterfacesets -A \
          -o jsonpath='{range .items[*]}{.metadata.namespace}/{.metadata.name}{"\t"}{.metadata.annotations.svc\.dpu\.nvidia\.com/interface-mode}{"\n"}{end}'

        # Legacy per-node ServiceInterface objects should be gone for migrated SFC sets
        # (using DPUCluster kubeconfig)
        kubectl get serviceinterfaces -A

        # NSI path: per-node shards in the DPF operator system namespace on the DPU cluster
        kubectl get nodeserviceinterfaces -n dpf-operator-system
        ```
