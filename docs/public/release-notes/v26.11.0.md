---
title: "DOCA Platform Framework v26.11.0"
---

This is the GA release of the DOCA Platform Framework (DPF) v26.11.0. It is based on v26.8.0 and
adds support for DOCA 3.6 together with bug fixes and scalability improvements.

The [release notes for v26.8.0](./v26.8.0.md) still apply for this release and the information
presented here is an amendment to the previous release notes.

### Revision History

| Date            | Description                                                            |
|-----------------|------------------------------------------------------------------------|
| October 2026    | General Availability (GA) release of DOCA Platform Framework v26.11.0  |

### Features

* **DOCA 3.6 support**
    * DPF v26.11.0 is validated with DOCA 3.6 and BFB `bf-bundle-3.6.0`, including the DOCA 3.6 host
      image and the DOCA 3.6 releases of HBN and SNAP.
    * The DPF hostdriver image now installs `doca-installer` and `mft` from the DOCA repository of
      its base image. This is required to install BlueField-3 BFBs with the DOCA 3.6 DMS.

### Improvements

* **Scalability for large fleets**
    * `ServiceChainSet` and `ServiceInterfaceSet` controllers skip the server-side apply of children
      that did not change, which keeps reconcile times low on clusters with thousands of nodes.
    * The `sfc-controller` cache is limited to the objects of its own node (`spec.node`), so the memory
      per DPU stays flat as the fleet grows.
    * The `sfc-controller` liveness probe no longer depends on the API server, so an API server outage
      does not restart the `sfc-controller` pods on every node at once.
    * The `pod-ipam-injector` reconciles only on changes that can alter the network configuration of a
      Pod and caches only the Pod fields it needs, which reduces its load.
    * Ready DPUs are reconciled when the corresponding Node in the DPU cluster changes, and DPUs are
      re-enqueued when the health check of their DPUCluster fails. Ready DPUs no longer have to be
      polled periodically.

### Fixed Issues from Previous Release

* **TLS verification failures during host agent DPU provisioning**
    * The DPU provisioning with the host agent no longer fails TLS verification when
      `kubernetesAPIServerVIP` is a hostname (for example on OpenShift) or when
      `registry.loadBalancerAddress` points to an external endpoint. Both are now part of the
      `bfb-registry` certificate SANs.

* **OS installation failure after a leader switch of the provisioning controller (Zero Trust)**
    * In Zero Trust, the `bfb-registry` host and NodePort that are baked into the DPU configuration
      stay stable across a leader failover of the provisioning controller or an upgrade, so DPU OS
      downloads keep passing TLS verification.
    * Internal Ref #4957820, #4930198

* **Control plane traffic leaking onto `oob_net0`**
    * Control plane traffic with `controlPlaneMTU` above 1500 no longer leaks onto the 1500-byte
      `oob_net0` port of the DPU.

* **DPU power on timeout**
    * The DPU power on timeout was increased for DPUs with long boot times.

* **[ServiceChainSet] Optional OVN configuration**
    * An optional OVN configuration is now handled correctly.

### Supported DPU Services

The supported DPU Services are updated to support DOCA 3.6. Other than that, the support status of
each service is unchanged compared to [v26.8.0](./v26.8.0.md#supported-dpu-services).

### Dependencies

* Supported DOCA BFB Image (BlueField-3):
    * `bf-bundle-3.6.0`
    * See the [DPF Compatibility Policy](../operational-readiness/upgrades/compatibility-policy.md) and
      [Platform Support](../platform-support.md) for the full support window.

### Installation & Upgrade Notes

#### Installation Notes

None.

#### Upgrade Notes

* The upgrade notes of [v26.8.0](./v26.8.0.md#upgrade-notes) apply when upgrading from a release
  older than v26.8.0.
* The CRDs of `ServiceChain`, `ServiceInterface` and `NodeServiceInterfaces` declare `spec.node` as a
  selectable field. No manual action is required.

### Known Issues and Limitations

The known issues of [v26.8.0](./v26.8.0.md#known-issues-and-limitations) still apply, with one
exception. The OS installation failure after a leader switch of the provisioning controller is
fixed for Zero Trust and no longer applies there. It still applies to Host Trusted deployments.
